## Findings that remain open

- **Framework and adapter advisories:** the locked Astro 5.13.2 and adapter baseline still matches published advisories. The inspected post-tar audit retained 50 affected package records: 1 critical, 42 high, 6 moderate and 1 low. These are package records, not 50 independently proven exploitable bugs. The [AVIF optimization advisory](https://github.com/withastro/astro/security/advisories/GHSA-26w7-cxv4-gfx2) requires a newer framework/Sharp baseline. Disabling image processing limits that configured path; the approved framework/adapter migration remains separate. The [tar advisory](https://github.com/advisories/GHSA-r292-9mhp-454m) documents a compatible fix, which this branch includes.
- **Historical credential investigation:** local history scanning identified a private-key candidate requiring owner confirmation and possible revocation. It is absent from current source. Retirement is unconfirmed. Sensitive details remain in local evidence; the key was not used for authentication and history was not rewritten.
- **Static-review candidates:** generic file/object access, intentional escaped HTML builders, controlled test payloads and trusted local-data rendering remain visible in the audit. A candidate is not automatically a vulnerability or an approved suppression. SPORA's retained HTML builder consumes versioned local JSON; it is not a sanitizer for arbitrary API data.
- **Third-party code and headers:** jQuery's inspected bytes have SRI. Other CDN resources lack verified immutable/CORS-compatible integrity coverage. DataTables CDN requests returned 403 from the review environment; browser checks substituted the matching pinned npm version. CSP is report-only. Passive scanning retains missing-enforced-CSP, SRI and cross-origin policy warnings. Enforcing isolation headers without reviewing external viewers could break them.
- **Local resources:** hostname/address checks do not perform DNS resolution or prevent DNS rebinding, and cannot guarantee that a public destination never redirects a browser to a private service. Trusted local-viewer mode and deployed browser permissions need environment-specific review.

The audit intentionally exits nonzero while these findings remain. No suppression makes them disappear, and no clean dependency-security result is claimed. ESLint 9 is a compatibility baseline shared with the other audit branches and carries lifecycle debt.

## Verification and limits

The focused final source round passed 176 tests without failures/skips; the normal Astro check reported zero errors/warnings. This includes actual compiled components, installed analyzers, subprocess failures and production HTTP requests. Nine controlled Chromium cases cover desktop/mobile rendering, annotation panels, native download controls and a harmless mutation that demonstrates the escaping assertion can detect executable markup.

The local Netlify adapter built with the real repository configuration and handled valid search, invalid limits, same-origin method rejection and the disabled optimizer path. The static header policy is in `netlify.toml`, not an incorrectly nested `_headers` file. Remote Netlify/CDN delivery is not verified. Cross-site requests may be rejected by Astro before application middleware runs.

CodeQL completed its JavaScript/TypeScript and workflow profiles. It retained three reviewed test-source matches: two literal hostname checks in the dependency-order fixture and a script-extraction regex over a known local component, rather than an HTML sanitizer. No production-code finding was reported by these profiles. The production JavaScript/TypeScript files match the extracted snapshot; later test-stub and Astro missing-value presentation changes are covered by the test suite. Workflow analysis reported no findings. Separate secret-history scanning retained 69 public study-accession matches and one historical private-key candidate; current-source scanning retained eight public accession matches. Raw evidence remains local. CodeQL does not analyze Astro templates as such. Browser checks use controlled APIs/vendor responses and exclude external viewer documents, analytics and live CDN reliability. Clipboard checks capture supplied values rather than verifying the operating-system clipboard. These checks do not establish screen-reader behavior or every conditional page configuration.

A complete live-catalogue build is **not verified**: the fail-closed build stopped on an upstream API timeout. The earlier stopped build must not be presented as successful evidence. Do not bypass the failure or publish a partial catalogue. A full container startup and remote deployment still need verification.

The security checks follow the shared root-Makefile/`makes/` convention and single recursive test entry. Shared controls retain the accepted metadata, numeric-filter, button and annotation behaviour alongside security validation. Future changes to these shared surfaces require reconciliation and affected checks; arbitrary merge order is not guaranteed.

Generated reports, raw payloads, scanner logs, exact revision/hash manifests and compatibility simulations stay under ignored `artifacts/security/`. Reviewers can regenerate the maintained audit with [the documented commands](security.md).
